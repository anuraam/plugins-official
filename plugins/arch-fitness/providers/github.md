# Provider: GitHub

Use this provider when `git remote get-url origin` contains `github.com`.

## Prerequisites

- **GitHub CLI** (`gh`) installed: https://cli.github.com
- Authenticated: `gh auth login`, or non-interactive `GH_TOKEN` / `GITHUB-TOKEN`

| Permission | Access | Purpose |
|---|---|---|
| **Contents** | Read & Write | Read code, push `arch/docs-*` branches |
| **Metadata** | Read | Resolve default branch and repo metadata |
| **Issues** | Read & Write | Read trigger issue body; post progress + fitness comments |
| **Pull requests** | Read & Write | Fetch PR diffs / merged windows; open docs PR |

The plugin does **not** use the GitHub MCP server.

---

## Resolving `owner` and `repo`

```bash
REMOTE=$(git remote get-url origin)
OWNER=$(echo "$REMOTE" | sed 's|https://github.com/||;s|git@github.com:||' | cut -d'/' -f1)
REPO=$(echo  "$REMOTE" | sed 's|https://github.com/||;s|git@github.com:||' | cut -d'/' -f2 | sed 's|\.git$||')
DEFAULT_BRANCH=$(gh repo view --json defaultBranchRef --jq '.defaultBranchRef.name')
```

---

## Reading the trigger issue

```bash
gh issue view "${ISSUE_NUMBER}" --json number,title,body,labels,state \
  --jq '{number, title, body, labels: [.labels[].name], state}'
```

Parse the optional config block between `ARCH FITNESS — START` and `ARCH FITNESS — END`. Extract:

- `Scope:`
- `Focus areas:`
- `Skip areas:`
- `Max findings:`
- `Output:`
- `Docs mode:`

CLI flags override these values.

---

## Posting the progress comment

Post immediately after inputs are resolved (task mode only):

```bash
gh issue comment "${ISSUE_NUMBER}" --body "$(cat <<EOF
## Architecture fitness in progress

Evaluating architecture constraints against the requested scope. A fitness report will be posted here when complete.

**Run plan**
- Scope: ${SCOPE_RESOLVED}
- Docs mode: ${DOCS_MODE}
- Focus areas: ${FOCUS_RESOLVED:-none}
- Skip areas: ${SKIP_RESOLVED:-none}
- Max findings: ${MAX_FINDINGS}
- Default branch: \`${DEFAULT_BRANCH}\`
EOF
)"
```

If posting fails, warn once and continue.

## Assembling changeset scopes

### Single PR

```bash
gh pr view "${PR_NUMBER}" --json number,title,baseRefName,headRefName,files,url \
  --jq '{number, title, baseRefName, headRefName, url, files: [.files[].path]}'
gh pr diff "${PR_NUMBER}" > /tmp/arch-fitness-pr.diff
```

### Branch vs default

```bash
git fetch origin "${DEFAULT_BRANCH}" "${BRANCH_NAME}"
git diff --name-status "origin/${DEFAULT_BRANCH}...origin/${BRANCH_NAME}"
git diff "origin/${DEFAULT_BRANCH}...origin/${BRANCH_NAME}" > /tmp/arch-fitness-branch.diff
```

### Merged PR window

Resolve `START` / `END` (ISO dates). Example for "last 3 months":

```bash
END=$(date -u +%Y-%m-%d)
START=$(date -u -v-3m +%Y-%m-%d 2>/dev/null || date -u -d '3 months ago' +%Y-%m-%d)

gh pr list --state merged \
  --search "merged:${START}..${END}" \
  --json number,title,url,mergedAt,files,author \
  --limit 200 \
  > /tmp/arch-fitness-merged-prs.json

echo "Merged PRs in window: $(python3 -c 'import json; print(len(json.load(open("/tmp/arch-fitness-merged-prs.json"))))')"
```

For each PR that touches constraint-relevant paths, fetch the diff on demand:

```bash
gh pr diff "${PR_NUMBER}" > "/tmp/arch-fitness-pr-${PR_NUMBER}.diff"
```

When the window is large, deep-read only the highest-signal PRs / files (see `agents/fitness-evaluator.md`).

## Opening / updating the docs PR

After `arch-doc-curator` commits and pushes `DOCS_BRANCH`:

### Reuse existing open PR

```bash
EXISTING=$(gh pr list --head "${DOCS_BRANCH}" --state open --json number,url --jq '.[0].url // empty')
```

If `EXISTING` is non-empty, skip create — the push already updated the PR. Set `DOCS_PR_URL="${EXISTING}"`.

### Create new PR

```bash
gh pr create \
  --title "docs(architecture): ${DOCS_ACTION} architecture constraints" \
  --base "${DEFAULT_BRANCH}" \
  --head "${DOCS_BRANCH}" \
  --body "$(cat <<EOF
## Summary

${DOCS_SUMMARY}

New and changed constraints are marked \`status: proposed\` and need human ratification before they are treated as project policy.

## Constraint changes

${CONSTRAINT_CHANGE_LIST}

## Related

Related to #${ISSUE_NUMBER}

---
Generated by the \`arch-fitness\` plugin.
EOF
)"
```

Capture the printed URL as `DOCS_PR_URL`. Omit the `Related` line when there is no issue attachment.

## Posting the fitness report comment

Render the report from `styles/fitness-report.md`, then:

```bash
gh issue comment "${ISSUE_NUMBER}" --body-file /tmp/arch-fitness-report.md
```

Apply the completion label:

```bash
gh label create "arch-fitness-complete" --description "Architecture fitness run completed" --color "0E8A16" 2>/dev/null || true
gh issue edit "${ISSUE_NUMBER}" --add-label "arch-fitness-complete"
```

When `Output: file <path>` or `Output: json` was requested, still post a short comment with the verdict + docs PR link, and write the full artifact to the requested destination.

---

## Chat mode (no issue)

Do not post comments. Print the fitness report to the conversation. If a docs PR was opened, include its URL in the printed report.
